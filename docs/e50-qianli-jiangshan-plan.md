## 一、为什么做这一套，以及它凭什么不与既有 26 套撞车

### 1.1 库里缺的两样东西

1. **运动语义缺"横向长卷流动"**。26 套里的运动主体要么是**单个物体**（E29 行星 / E35 光轴 / E42 星轨），
   要么是**原地介质**（E43 海浪 / E44 云与光柱 / E46 雾 / E47 雪 / E48 烟 / E49 鸟群）。
   ⛔ **没有一套的画面本体是"一整幅横向展开、多层以不同速度流动的长卷"**。
   E48 的沙丘是**静物**（只有烟和驼队动），E49 的视差只发生在**底部 1/5 的带**里（树带 ≈6 px/s）。
2. **色相族缺"矿物青绿 + 绢本暖底"**。现有冷蓝（E43/E47）、暖红（E48）、月白（E44）、深空（E41/E42）都有，
   ⛔ **石青 / 石绿 / 赭石 / 暖黄绢底**这一族一个都没占。它同时是本主题最不可让渡的识别度（需求 §3.2）。

⇒ 这两个缺口是同一件事的两面：**「一幅会动的青绿长卷」在本库里既是新运动，也是新颜色**。

### 1.2 ⛔ 与最近亲的区分点（三套必须"读起来不是同一张图"）

| | **E43 海边** | **E48 大漠孤烟** | **E49 鸟群掠过荒野** | **E50 千里江山（本主题）** |
|---|---|---|---|---|
| 主体运动 | 浪**向岸推进**（纵向） | **静物** + 一柱烟（纵向） | 群体**自组织**（横向、无序） | **多层长卷横向流动**（有序、匀速） |
| 画面是否整体位移 | ❌ 原地 | ❌ 原地 | ⚠️ 仅底部 1/5 带 | ✅ **全画面分层流动** |
| 色相族 | 冷蓝海水 | 饱和暖红 + 黑沙 | 暮色冷天 + 暖地 | ⭐ **青绿 + 暖黄绢底** |
| 有无发光天体 | 无 | ⭐ 低垂巨大落日 | ⛔ 刻意不画 | ⛔ **不画日盘、不画月** |
| 天空占比 | 上 1/2 | 上 3/5 | ⭐ 压倒性（>3/4） | 上 **0.42**（山占了中部） |
| 留白位置 | 浪与滩 | 沙丘与天 | 天空 | ⭐ **江水带 = 横向留白**（下部 0.38） |
| 第一读感 | 俯冲 / 湿 / 冷 | 热 / 静 / 竖 | 开阔 / 动 / 横 | **古 / 缓 / 横 / 纸本** |

⭐ **唯一关键区分点：本主题的画面本体是"一张平铺的画"，不是"一个场景"。**
其余全是推论 —— 因此三条硬性后果：

- ① 每一层都是**沿 X 无缝平铺的带**（§四），⛔ 不是"画面上摆几个山形"；
- ② 运动**匀速、无节奏性**（需求 §四.6 的 1.3× 上限就是这条的量化），⛔ 不跟鼓点走；
- ③ 质感来自**纸本**（绢纹 + 做旧 + 皴擦），⛔ 不来自光效 —— 这一条决定了 §七 的填充预算怎么花。

### 1.3 需求「频谱融入山水」在本仓的具体含义

需求的原话是"⛔ 不得出现传统突兀的柱状频谱条"。**本仓 26 套里其实早已没有裸柱状图**
（E05 圆环、E13 网格等是"频谱几何化"，不是柱）。本主题把这条推到底：

> **律动只作用于"材质参数"（透明度 / 平铺相位 / 色偏移 / 流速），⛔ 绝不作用于"几何轮廓"。**

⇒ 山体轮廓、水线、地平线**全是静态烘焙结果**；频谱改的只是**α、偏移、色温**。
这一刀切下去，"频谱破坏静谧意境"（需求 §十一.3）就没有物理发生的路径了。
这是本主题的**第一设计约束**（D5）。

## 二、主题身份（已定稿，落地时才动源码）

```kotlin
QIANLI_SCROLL(R.string.visualizer_theme_qianli_scroll, "千里江山", Tier.ADV, "50", needsParticleBudget = false)
```

- **枚举键** `QIANLI_SCROLL` · 中文名「千里江山」· `Tier.ADV` · `ordinalLabel = "50"` · `needsParticleBudget = false`。
- **为什么是 `"50"`**（已按源码核对 `AppSettings.kt:126` 起的 `VisualizerTheme`）：
  工作树当前 **26 套**，已占用编号最大者为 `"49"`（E49 鸟群），`"48"`（E48 大漠孤烟）亦已落地；
  **`"45"` 空置**（E45「黑洞」方案 `docs/blackhole-visualizer-plan.md:260` 为它预留了 `"45"`，但该方案至今未开工）。
  ⇒ 本主题取 `"50"`，落地后是**第 27 套**，与 E45 是否先落地**无冲突**。
- **为什么 `Tier.ADV` + `needsParticleBudget = false`**（与 E44 / E46 / E47 / E48 / E49 完全同形制）：
  档位如实标注"比 BASIC 重"（6 层平铺 blit + 8 类烘焙位图），但本效果**一个粒子都不画**、
  ⛔ **不读** `ctx.quality.maxParticles`（数量只按 `fx.level` 三档表调）⇒ 第 4 参是**可核对的事实**。
  `VisualQuality.supports` 的 `ADV -> !needsParticleBudget || maxParticles > 0` 因此恒为真，
  **三档全部可选**（含 LOW）。
  ⚠️ **别误标 `true`**：那会让 LOW 档「能渲染却不可选，切走即永久回不来」（2026-10-01 用户裁决修掉的那类缺陷）；
  ⚠️ **也别改挂 ULTRA** —— 本效果**不用帧缓冲**，与 `allowFramebuffer` 无关。
  ⚠️ 若日后渲染器真的读取 `maxParticles`（例如改用预算控光尘数量），`ParticleBudgetGateTest` 的源码扫描会与本标注对撞 ⇒ 必须同步改成 `true`。
- **显示名两语必须同时加**（`values/strings.xml` + `values-en/strings.xml`）：缺一份**编译不报错、渲染时崩**，
  门禁 `VisualizerThemeStringsGateTest`（G1）专抓这一条。英文名 → 开放项 **O4**。
- **注册链共四处**（缺一即"效果在库里但选不到/渲染成空白"）：
  1. `AppSettings.kt` 枚举项；2. `VisualizerRendererFactory.kt:49` 的 `when` 分支；
  3. 两份 `strings.xml`；4. `FxCoverageScanTest.kt` 的 `covered` 名单登记（§七.4）。

## 三、画面构成：一条五层长卷

### 3.1 图层序（⛔ 顺序即遮挡 —— 因为全项目禁用 `clipPath(`）

API 22 创维在 `Region::createTJunctionFreeRegion` 原生 SIGSEGV ⇒ **全仓红线**
（`docs/blackhole-visualizer-plan.md:25`）。本主题的山压山、雾遮山、岸切水，
**遮挡只由绘制顺序产生**，⛔ 不许写任何裁切/遮罩代码（与 E48 驼队被沙丘吃掉腿是同一手法）。

| 序 | 层 | 内容 | 每帧图元 | 频谱是否驱动 |
|---|---|---|---|---|
| L0 | **绢底天幕** | 竖向渐变（暖黄→青灰）+ 绢纹 + 做旧斑 | 1 全屏 blit | ❌（⚠️ 段落能量只改其一张覆盖层 α） |
| L1 | **远景山峦 + 远雾** | 淡青灰峦头带（平铺）+ 一条雾带（平铺） | 2 | ✅ α / 平铺速度 |
| L2 | **中景青绿峦头** | 石青石绿主山（平铺）+ ⭐ **轮廓淡金光晕**（独立一层平铺位图） | 2 | ✅ 光晕 α、绿饱和偏移 |
| L3 | **近景坡石汀岸** | 墨色 + 赭石坡脚、矶石、简笔树（平铺） | 1 | ✅ 轻微 α |
| L4 | **江水留白** | 横向细波纹 + 高光丝（平铺，1–2 带） | 2 | ✅ 低频驱动波幅 α |
| L5 | **光尘** | 水天之间细碎光点（⭐ 烘成一张点阵平铺位图，⛔ 逐粒 blit） | 1 | ✅ 高频驱动 α + 相位 |
| L6 | **grade（暗角 + 颗粒）** | 与 E46/E47/E48/E49 同三段式：烘进**一张**位图 | 1 全屏 blit | ❌ |
| L7 | **印章** | 「扫地老师」朱砂印，屏幕固定坐标 | 1 blit | ❌ **恒定不呼吸**（§六.3） |

**目标图元数：11–12 ops/帧**（§七 预算表）。
⚠️ L7 印章**必须画在 grade 之后**，否则暗角会把朱砂红一起压暗、四角不匀（D8）。

### 3.2 构图锚点（⛔ 全部归一化，不写死 px）

```
skyTopY      = 0.00H                     // 绢底最上：偏冷的青灰
horizonY     = 0.620H                    // 江面顶界 —— ⭐ 本主题的"留白"从这里开始
waterBottomY = 1.00H                     // 江水带 = 底部 0.38H
farRidgeY    = 0.42H … 0.58H             // 远景峦头只露在山脊以上
midPeakY     = 0.20H … 0.55H             // 中景主峰（画面的重心，青绿最饱和处）
nearFootY    = 0.66H … 0.88H             // 近景坡石，压在江水带之上、只占底部
sealCenter   = (W − inset − s/2, inset + s/2)   // 右上角，s 见 §六.3
```

- ⭐ **江水是"横向留白"**：中部偏下必须有一条**基本空着**的亮带，这是长卷读感的来源。

## 四、长卷滚动与无缝循环（本套的核心难点）

### 4.1 平铺机制：`ImageShader(TileMode.Repeated)` + 画布平移

选定与 E48「贴地浮沙带」**完全同形制**的做法：单层画笔 = `ShaderBrush(ImageShader(bmp, Repeated, Clamp))`
（X 向 `Repeated` 无缝循环、Y 向 `Clamp` 不外溢），逐帧只走**一次画布平移 + 一次 `drawRect`** ⇒ **1 op/层**。
参考：`DesertSmokeRenderer.kt:787-789`、`:614-621`（原型的"平铺第二张补右缘"在 Kotlin 侧被折叠成 1 op）。

- ⛔ **不用"两张位图来回 blit"**：那是 2 op/层，且右缘补缝逻辑在多周期下极易错（E48 已在原型里用第二张补缝，Kotlin 侧专门折叠掉）。
- ⛔⛔ **位移绝不靠 `Shader.setLocalMatrix`**：E43 真机实测在硬件画布上**静默失效**（画了个不偏移的），
  修法是把映射移到 **Canvas 变换**里 ⇒ 本套所有滚动一律 `canvas.translate`，⛔ 不留任何 local matrix 代码。
- ⚠️ 平铺 + 平移的画布必须在 `drawIntoCanvas { }` 里成对 `save/restore`（⛔ 逐图元 `save/restore`，E48 已列为红线：一次帧内多次 save/restore 是成本项）。
- ⭐ **平铺的锚点与缩放必须显式做**（2026-10-18 原型现场补，门禁 G12 判这三件事）：
  位图平铺的原点是**当前画布变换的原点**，不是 `drawRect` 的左上角。所以每层必须
  ① `canvas.translate(-offsetPx, y0·H)` 把 **tile 第 0 行钉在带区上沿**（只平移 x ⇒ 整个山形上移 `y0·H`、
  且在设备行 `tileH` 处**纵向重复一次**，山脚被切出一条水平台阶——原型里真实发生过，G1/G2 只量 tile 自身，抓不到它）；
  ② `canvas.scale(1/sc, 1/sc)` 把 LOW/MEDIUM 的低分辨率烘焙**放大回显示尺寸**（§7.2 缓解项⑤"LOW 档 W/2 降采样"的前提）；
  ③ 缩放后用户单位就是 tile 像素，矩形高度取**位图自身高度 `bmp.height`（整格，整数）**，
  ⛔ 不取 `(y1−y0)·H·sc` 的浮点值 —— LOW 档实测 302.4 vs 位图 302 行 ⇒ 多画 0.4 格，
  等于把**下一格副本的第 0 行**叠进带底（原型 G12 在 LOW 档量到的"2 段"就是这么来的）。
  带区显示高度 = `bmp.height / sc`，与 `(y1−y0)·H` 之差 ≤1 设备像素（H2/G12 各有一条断言钉住）。
  三者合一后 Y 向 `Clamp` 才成立（带区恰好一个 tile 高，外溢无从发生）。

### 4.2 无缝的**构造性保证**：一切横向形状都做成 `W` 的周期函数

> 接缝不是靠"调参调到看不出来"，而是靠**轮廓函数在数学上以 W 为周期** ⇒ `f(0) ≡ f(W)` 恒成立。

**峰脊线**（每层一条）：

```
ridge(x) = base + Σ_{k=1..K} A_k · sin(2π k x / W + φ_k)      // ⭐ 有限傅里叶级数
A_k ∝ k^(-1.4)   (1/f 地貌感),   φ_k 来自 VisualizerRandom（固定种子）
```

- ⛔ **禁止任何非周期项**进入横向坐标：连续值噪声、随机游走、累积 `+= rng` —— 它们必然在 `x=W` 处不闭合。
  （这是需求 §四.4「接缝必须无缝、不得出现明显跳变」唯一可靠的实现路径。）
- **皴法纹理 / 矾头 / 矶石 / 波纹 / 光尘点阵**：用**周期化 value noise** —— 格点索引 `mod N`
  （⭐ 原型定稿的写法是 `u = (x / W) · N`，`N` = **一个周期内的格数**（整数），格宽 `W/N` **不必整除**；
   Kotlin 侧必须同形制，⛔ 不要写成 `floor(x / cellW)` —— 那种写法在 `W` 不整除格宽时**在缝上露馅**，H3 已把这条钉住）
  ⇒ 平铺接缝**像素级相等**。随机点位一律按 `x mod W` 落位，⛔ 允许越界的点必须在**烘焙期**复制成两份补缝
  （⛔ 不在逐帧画的时候处理）。

**门禁 G-seam（= 原型 G1/G12，两侧都判、可复跑）**：
1. `ridge(0) == ridge(W)`（相对误差 ≤ 1e-6）；
2. 一阶差分在接缝处连续：`ridge(W) - ridge(W-ε) == ridge(ε) - ridge(-ε)`（同一斜率，容差内）；
3. **机制判据（G1a）**：同一周期图平移 `P/2` 再切一张 tile ⇒ `tile2[列 c] ≡ tile1[列 (c+P/2) mod P]`
   **山体本体逐字节相等**（内部列差必须为 0；两张 tile 各自的**边界列**豁免，实测 ≤16 字节、单行 α ≤16 LSB）。
   ⛔ 不判"最左列 ≡ 最右列"（那是要求函数在缝处持平，不是平铺接缝的判据）；
   ⛔ 也不用"两周期宽的参照图"（改变路径总长 ⇒ AA 分块噪声 ±1 LSB 铺满 2.3% 列，真缺陷被淹没）。
4. **外观判据（G1b）**：把 tile 平铺两次，接缝那一列"跳变 ≥16 LSB 的行数"与"最大跳变"都 **≤ 内部最坏列**
   （单看 max 会把"接缝和笔触一样陡"误判成合格 —— MEDIUM 实测接缝 max 128 / 内部 max 167）。
5. **锚点判据（G12）**：blit 后 tile 第 0 行贴在**带区上沿**、带内**不纵向重复**、显示按 `1/sc` 放大；
   矩形高度取**位图自身高度**（整格），⛔ 不用带高浮点值（LOW 档会多画 0.4 格 ⇒ 下一格副本的第 0 行叠进带底）。

缩 `W`（③）单独不够（47.53 > 46），且会缩短单圈时长（越短越容易看出重复）⇒ 排在最后。⇒ 开放项 **O6** 待裁。

### 4.4 音乐只允许"轻微推一把"

```
v_layer(eff) = v_layer(base) · (1 + 0.30 · energyS)     // 上限恰为需求 §四.6 的 1.3×
```

- `energyS` = `AudioFrame.energy` 经 `AudioSmoother`（§五.4）；⛔ **不用 `beat`**（鼓点 ⇒ 瞬间跳速 ⇒ 破坏悠远）；
- ⛔ 不用 `frame.spectrum`；⛔ 各层共用同一个 `energyS` ⇒ 层间**速度比恒定**（比例被破坏 = 视差穿帮）；
- 静音时 `energyS → 0` ⇒ 速度自动回到 base，⛔ 绝不停滞。

### 4.5 整体呼吸 1–3%

需求 §5.3「画面轻微呼吸，幅度 1%–3%」。落实方式：

- **⛔ 不用全屏缩放 redraw**（会重新经过所有层）；用**各层 `dstRect` 上下沿微扩**或 `canvas.scale` 于位图 blit。
- ✅ `canvas.scale` + **矩形/凸四边形 blit** 在 API 22 真机是**活的**（E43 线性渐变 + `setLocalMatrix`… 已改；
  concat + 凸四顶点实测 alive 2026-10-13）。
- ⛔ **绝不 `canvas.concat` × 非凸/自交填充路径** —— 同一 34 顶点多边形，屏幕空间 80 帧全填、
  经 `concat(axisMatrix)` **80 帧 0 像素**（E46 真机定位，`TripodFillMechanismGateTest` 守）。
  ⇒ 本主题逐帧**不画任何非凸 Path**，全部是位图 blit，天然避开该陷阱；几何复杂度都放在烘焙期。
- 驱动：`sectionEnergy`（8s 滑动均值）+ `pulse`，`scale ∈ [1.000, 1.030]`，⛔ 不乘 `bass`。

### 4.6 时间与生命周期（照抄既有铁律）

- **时间只有一个自变量 `tSec`**（由 `fx.dt` 累加），⛔ 不是 `ctx.nowMs`、⛔ 不是墙钟（E48 同律）。
  ⚠️ `fx.dt` 本身已是秒，⛔ 不再除 1000（E44 偏差 D31）。
- ⛔ 渲染器**不写生命周期代码**：舞台 `onPause` 停帧 ⇒ 滚动与音频自然停；恢复即续（需求 §四.8、§九.10 由架构满足）。
- ⚠️ **画质变化会重入 `onEnter`（不经过 `onExit`）** ⇒ `onEnter` 首行必须 `releaseAll()`（E48 逐字留过此痕）。
- 位图活在 API 22–25 的 **native heap** ⇒ 每张烘焙位图必须进 `onExit`/`releaseAll` 的释放路径。

## 五、频谱 → 山水的映射

### 5.1 通道来源（⛔ 只用律动通道）

| 视觉量（层） | 音频源 | 变化区间 | 说明 |
|---|---|---|---|
| L1 雾带 α 与流速 | `bass`（20–250Hz，`BASS_END=39`） | α `0.10 → 0.30`；流速 `×1.0 → ×1.3` | 低频只推**雾和水**，⛔ 不推山 |
| L4 江水波幅 α | `bass` | `0.16 → 0.34` | 与雾**同源不同曲线**（水响应快于雾） |
| L2 轮廓淡金光晕 α | `mid`（250Hz–3kHz，`MID_END=55`） | **`0.10 → 0.34`** | ⭐ 本主题唯一"发光"通道，也是最主要的"有音乐"信号 |
| L2 青绿饱和偏移 | `mid` | `ΔS ≤ 0.06`、ΔH ≤ 4° | 靠一张**饱和覆盖层**的 α 实现，⛔ 不逐帧重烘 |
| L3 近景雾气 α | `mid` | `0.06 → 0.16` | 需求「山脚雾气亮度」的落点 |
| L5 光尘 α + 平铺相位 | `treble`（3k–20kHz） | α `0.05 → 0.22`；相位 ±40px | 需求「细碎光点」落点；⛔ 飞鸟（撞 E49，见 O2） |
| 各层速度 | `energy`（≤1.3×，§4.4） | — | — |
| L0 冷暖 / 做旧强度 | `sectionEnergy`（8s 均值） | 色温 ≤ 2 单位；颗粒 α `0.026 → 0.034` | "段落响度决定画面情绪"，无节奏性 |
| 整体呼吸 | `sectionEnergy` + `pulse` | scale `1.000 → 1.030`（§4.5） | — |

### 5.2 为什么这套映射"读起来不像频谱"

因为**没有一条映射通向几何**（D5）。频谱能改变的只有**透明度、平铺相位、色偏移、流速**四种量，
而这四种量的变化上限都被压到"盯着看才发现刚才亮了一点"的量级 —— 需求 §5.1「以融入山水的方式呈现」的实现学定义就是这句。

### 5.3 ⛔ 不读 `frame.spectrum`（D5 的技术面）

`AudioFrame.spectrum`（64 柱，已 gamma 压缩）是**显示通道**。本主题一条都不读：

- 拿它画任何东西 ⇒ 必然出现"64 个随频率排列的几何体" = 柱状频谱换了个方向（需求 §5.1 禁止项）；
- 拿它驱动律动 ⇒ 强弱差异被 `DISPLAY_GAMMA = 0.75` 压扁（历史 BUG ⑨-b，`AudioFrame.kt` 类头明写「二者不可混用」）。

⇒ 律动只用 `bass / mid / treble / energy / sectionEnergy / pulse`，
需要"鼓点强弱差异"时才用 `bassRaw`（本主题**不需要**，因为⛔ 不跟拍）。
⚠️ 这条要写进门禁（G-通道：源码扫描渲染器，出现 `frame.spectrum` / `.spectrum[` 即失败）。

### 5.4 平滑：attack 慢、release 更慢（与烟花类相反）

既有 `AudioSmoother(attack, release)` 默认 `0.35 / 0.06`（"鼓点要快 attack"）。本主题**刻意改慢**：

```
雾 / 水 / 速度：attack 0.10  release 0.035     // 几帧才见得起势，落得更慢
淡金光晕    ：attack 0.18  release 0.05      // 唯一允许稍快的一路（"有音乐"的主信号）
光尘        ：attack 0.24  release 0.07      // 最亮的一路，但仍⛔ 不用 0.35 以上
段落 / 呼吸 ：attack 0.04  release 0.02      // 情绪级，几乎无感
```

判据（进 G-平滑）：**连续 60 帧内任一 α 的单帧变化量 ≤ 其总动态范围的 6%** ⇒ 物理上排除了频闪。

### 5.5 无音频时的优雅降级（需求 §八.2/§八.4 → 现状即满足）

- 停止播放/无音轨时分析层仍在输出 `pulse`（快起慢落脉冲）与呼吸；本主题以它作**降级动画源**
  （与 E42 星空「静音不全黑」同一路子）。
- **α 下限表**（⛔ 任何通道不得把对应层降到 0）：
  `L1 雾 ≥ 0.10`、`L2 光晕 ≥ 0.10`、`L4 水 ≥ 0.16`、`L5 光尘 ≥ 0.05`、`L0/L2/L3 山体 ≡ 1.0`。
  ⇒ 静音画面 = 一条缓缓流动、带极淡金光的青绿长卷。
- ⛔ 不弹权限框、⛔ 不报错、⛔ 不黑屏 —— 因为本主题**根本没有音频输入这条路**（裁定 5），
  需求 §八.4 的"降级"在本仓是**默认态**。

## 七、性能与内存预算（⭐ §7.1/§7.2 已由原型 harness 再生为实测；真机列仍待 §十一 回填）

### 7.1 逐帧图元预算（⭐ ops/铺屏为 H6 实测，1800 帧推进）

| 档 | 层数 | ops（L0→L7） | 铺屏填充数 | 判据 |
|---|---|---|---|---|
| HIGH | 8 | **11**（峰值=均值=11，逐帧恒定） | **5.13 屏** | ⛔ 不超 14（H6 目标 ≤12 ✅） |
| MEDIUM | 8 | **11**（同上） | **5.13 屏** | ⛔ 不超 14（H6 目标 ≤11 ✅） |
| LOW | 6 | **10**（峰值=均值=10） | **4.74 屏** | 目标 ≥50fps（H6 目标 ≤10 ✅） |

⚠️ 原估的"12 op / ≈8.5 屏"高估了：**每层平铺只 1 op**（`ImageShader(Repeated)` + 一次 `drawRect`），
且 grade/印各 1 op ⇒ L0 1 + L1 2 + L2 2 + L3 1 + L4 2 + L5 1 + grade 1 + 印 1 = 11；
铺屏按**实际带高**累加（远 0.46 + 中 0.56 + 近 0.28 + 水 0.79 + 雾 0.20 + 尘 0.28 + 天幕/grade 各 1）≈ 5.13 屏。
LOW 少的那 1 op 是 L4 高光带（页面里 `TIER !== 'LOW'` 才 blit，α 仍照常计算）。

依据真机模型：**~0.41–0.47 ms/图元 + ~24.6 ms 固定成本**（无条件离屏层 + 全屏通道）
⇒ 60fps 需要约 ≤18 图元/帧。⚠️ 但该线性模型**在"多小 op 合并成少大 blit"后会过预测**
（E16 合并后实测 44.1fps vs 模型 27fps）⇒ 本套全是**大位图 blit**，真实成本更可能落在"填充率"而非"op 数"。
⇒ **合并后必须重测斜率，不许继续引用合并前的数字**（既有明确教训）。

### 7.3 分帧烘焙

沿用 E47/E48 的 `*Bakes.BAKE_BUDGET_MS` 模式：**首帧 boot + 若干帧续烘**，
烘序按「**缺了画面最不完整**」排（L0 绢底 → L2 主山 → L1 远山 → L3 近景 → L4 水 → L2 光晕 → L5 光尘 → grade → 印）。
⛔ 一次 `onEnter` 里同步烘完 10 张 ⇒ 掉帧甚至 ANR（既有返工教训）。
⚠️ 两段式启动的**次帧**必须并入 `bootPending` 判据（E48 2026-10-16 真机第二轮修复踩过）；
且⛔ 不要在续烘期间 `return`（只画一条天幕 = 丢山丢水 = 用户读成黑屏）。

### 7.4 后处理三段式（必须照做，否则白补一次全屏 drawRect）

- `postFx` 留**字面量**当门禁证据 + `vignetteOverride` 恒 `0f` 关断基类绘制（暗角/颗粒由 grade 位图承担）；
- ⛔ **绝不退回 `PostFx.NONE`**：`NONE` 让 `hasFullScreenPass()` 恒假 ⇒ `RendererFx.needsDamageCoalescer`
  在 LITE/FULL **也为真** ⇒ 每帧多一次**整画布** `drawRect`（肉眼不可见、铺屏 1.000 屏）。
  E46 踩过两次、E47 逐字抄错再踩一次（`FxCoverageScanTest.kt:58-66` 留痕）；
- 新渲染器必须**同步登记进 `FxCoverageScanTest` 的 `covered`**（`FxCoverageScanTest.kt:41`）；
  名单 stale 判据会抓"文件存在但名单缺失"。
- ✅ 本主题 L0 本身就是全屏 blit ⇒ **天然满足"每帧至少一个全屏 op"**（P-3 原生 SIGSEGV 的规避条件）。

### 7.5 fps 目标（⛔ 与需求 §九.9 不同）

- 手机/平板中端机：目标 ≥55fps（需求达成）；
- **创维 API 22 基准机**：HIGH/MEDIUM ≥30fps 且无明显卡顿感、LOW ≥50fps（本仓 E42–E49 实际验收线）。
- 读数手段：`adb shell settings put global nasmusic_fps 1` 右上角标（自服务，0.5s 滑窗，封顶 60），
  `dumpsys gfxinfo` 在该 TV 上恒空，⛔ 别指望。
